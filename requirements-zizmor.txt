# The workflow-security gate, zizmor, installed by
# .github/workflows/actionlint.yml with --require-hashes (issue #127): the
# tool that judges every workflow's supply chain is installed byte-for-byte
# as reviewed, never whatever the index serves at run time. Pinned like every
# other tool in the repo so a release cannot turn CI red on an unchanged
# commit.
#
# Why a requirements file when the install is one step in a workflow:
# Dependabot's pip ecosystem reads manifest files and never the pins inside a
# workflow `run:` block, where an inline `pip install zizmor` is invisible to
# automation and can only go stale (issue #50); here it joins the manifests
# the weekly Dependabot pass already watches.
#
# The pin below is the only place this file may name a version (issue #300).
# Dependabot rebuilds the --hash lines from the declaration it matched, and it
# matches the first declaration whose name is this package and whose
# requirement is the one being replaced: a comment repeating the pin is
# matched first, carries no hashes, and the bump then rewrites the version
# while leaving the old digests behind, so the --require-hashes install fails.
# Keeping the pin out of the comments is what makes a bump arrive green;
# tests/test_ci_workflows.py holds that shape.
#
# One package, no transitives: zizmor's PyPI package ships its Rust binary in
# the wheel and declares no dependencies, so the hash check has nothing
# unpinned to trip over.
