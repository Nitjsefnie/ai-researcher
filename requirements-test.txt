# Test-only toolchain, pinned for the same reason as requirements-dev.txt.
#
#   pytest — the runner. NOT interchangeable with `unittest discover` here:
#   tests/ has no __init__.py and the tests do `import build` from the repo
#   root, so discovery must come from a runner invoked as `python3 -m pytest`
#   at the root, where `-m` puts the cwd on sys.path. The bare `pytest`
#   binary fails for exactly that reason — see .github/workflows/tests.yml.
#
#   coverage — measures the suite; the workflow calls `coverage report` and
#   `--fail-under` as separate steps so the summary still renders when the
#   gate is red.
#
#   playwright — tests/test_browser.py drives the built page in a real
#   headless Chromium. The browser binary itself is not a pip package;
#   CI installs it through scripts/ci/install_chromium.py, which verifies
#   the browser archives against committed sha256 digests before playwright
#   may execute them (a bare `playwright install` performs no integrity
#   check). Its digest table, scripts/ci/chromium-digests.json, is keyed to
#   this playwright pin: a bump's fix is running
#   scripts/ci/update_chromium_digests.py and committing its rows with it.
#
#   pyyaml — tests/test_refresh_workflow.py parses the publish workflow with
#   it, pinning the gating contracts between steps structurally.
